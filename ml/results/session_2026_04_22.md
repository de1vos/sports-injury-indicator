# Session Summary — 22 April 2026

## What we did

### 1. Diagnosed the existing state
The plan to collect historical PL match stats (2022–2024) was already complete from a prior session. Model was trained on PL-only data with a test PR-AUC of 0.446.

### 2. Added cup + European match data
Built two new scripts (`collect_fixtures_cups.py`, `collect_match_stats_cups.py`) and updated `build_match_stats.py` to ingest FA Cup (45), EFL Cup (48), UCL (2), UEL (3), and UECL (848) fixtures for all 4 seasons (~800 API calls on the Pro tier).

**Goal:** enrich workload features (ACWR, match density, minutes) with midweek games the model was previously blind to. A congested UCL + PL week now looks different to the model instead of identical to a quiet one.

New raw files: `data/raw/fixtures_{league}_{season}.json`, `data/raw/match_stats_{league}_{season}.json`

A `competition` column was added to `match_stats.csv` (`"PL"`, `"FA Cup"`, `"UCL"`, etc.).

### 3. Fixed a data leak — non-PL players
The cup/Euro fixtures brought in ~4,800 players from opposing teams (e.g. Leipzig, Bayer Leverkusen) who have no injury records in our database, so they were all labelled `injured_next_90d = 0`. Added a PL player filter in `engineer_target.py` to keep only the 1,429 players who actually appeared in PL matches.

### 4. Added body-region injury features
Extended `engineer_injury_features.py` with 6 new columns that break down injury history by body region using `BODY_REGION_MAP` from `config.py`:

| Feature | Description |
|---|---|
| `muscle_injuries_last_24m` | Hamstring, quad, calf, adductor injuries in last 24 months |
| `knee_injuries_last_24m` | ACL, meniscus injuries in last 24 months |
| `ankle_injuries_last_24m` | Ankle injuries in last 24 months |
| `days_since_last_muscle_injury` | Recency of last muscle injury |
| `days_since_last_knee_injury` | Recency of last knee injury |
| `same_region_recurrence_flag` | 1 if 2+ injuries to the same body region in last 24 months |

### 5. Tested and rolled back PL fixture filter
Tried filtering training rows to PL fixtures only (to better match the production scenario where we predict only before PL matches). It slightly hurt performance (0.487 → 0.478) because it removed ~7k training rows on an already-lean dataset. Reverted — cup/Euro rows as training examples provide useful additional workload context.

## Results

| Version | PR-AUC (test) | Train PR-AUC | Train/test gap |
|---|---|---|---|
| PL-only baseline | 0.446 | 0.718 | 0.272 |
| + cups, all players | 0.484 | 0.716 | 0.232 |
| + PL player filter | 0.487 | 0.731 | 0.244 |
| + PL fixture filter + region features | 0.478 | 0.734 | 0.256 |
| **+ region features only (final)** | **0.485** | **0.739** | **0.254** |

**Random baseline** on this dataset (35% positive rate) = PR-AUC ~0.35.

**Our model at 0.485 is 38% better than chance.**

In practical terms: if you flag the top 100 players as high risk before a gameweek, roughly 40–50 of them will actually get injured in the next 90 days.

## What's still limiting us

The train/test gap (~0.25) indicates the model is learning some era-specific patterns from 2022–2024 that don't fully transfer to 2025. The biggest remaining levers are:

1. **Cross-validation** — time-series CV across multiple folds to better tune hyperparameters
2. **`/fixtures/lineups`** — distinguish "benched for rest" vs "absent injured"
3. **`/fixtures/events`** — catch in-match injury substitutions (ground-truth mid-match injuries)
4. **Actual international match minutes** — replace the crude break-calendar flag with real minutes played

For a 55-feature XGBoost model predicting soft-tissue injury 90 days out — one of the noisiest targets in sports science — a PR-AUC of 0.485 is a respectable real-world result.
